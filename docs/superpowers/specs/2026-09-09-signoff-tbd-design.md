# วัน Sign Off ที่ยังไม่กำหนด และคำเตือนเมื่องานย่อยเลยกำหนด

**วันที่:** 2026-09-09
**ขอบเขต:** `index.html` — งานใน Gantt แผนงานโครงการ (`PIMPL` / `GCTX==='pi'`)

## ที่มา

ผู้ใช้ส่งสเปรดชีตติดตาม BRD ที่ใช้งานจริงมาให้ดู แล้วถามว่าจะออกแบบระบบยังไงให้ครอบคลุม

โครงของสเปรดชีตคือ **วงจรเวอร์ชัน** ไม่ใช่แค่การเลื่อนกำหนด

```
ร่าง → ส่ง V.1 → อีกฝ่ายตรวจ → feedback → แก้ → ส่ง V.2 → … → Sign Off
```

คอลัมน์: `V.1 Target` · `Version.1 status` · `V.2 Target` · `Open Issues / GAP` · `Target Sign Off`

**ข้อสังเกตที่สำคัญที่สุด: แถวสีส้มทุกแถวมี `Target Sign Off = TBD`** (5 จาก 12)
ส่วนแถวสีเหลืองมีวันครบ นั่นไม่ใช่ "ช้ากี่วัน" แต่คือ **"ยังไม่มีใครรับปากว่าจะเสร็จเมื่อไหร่"**
ซึ่งอันตรายกว่าการช้าที่รู้กำหนด และเป็นสถานะที่ระบบพูดไม่ได้เลย

## ปัญหาที่ต้องตัดสินก่อน: 3 วิธีพูดเรื่องเดียวกัน

รอบทบทวนถูกแทนด้วย 3 อย่างพร้อมกัน — งานย่อย (`CIVIL - Review & Feedback_Round 1`)
· `dueLog` · `st='In Review'` + `rvw` ถ้าเพิ่มฟิลด์เวอร์ชันเข้าไปอีกจะกลายเป็น 4 วิธี แล้วข้อมูลจะขัดกันเอง

**ทางที่เลือก: ให้แต่ละอย่างมีหน้าที่คนละชั้น ไม่ทับกัน**

| ระดับ | `d.e` หมายถึง | เลื่อนได้ |
|---|---|---|
| งานหลัก (`BRD01`) | **Target Sign Off** | ✓ `dueLog` |
| งานย่อย (รอบทบทวน) | **วันที่ต้องส่งกลับ** | ✓ `dueLog` |

`st='In Review'` + `rvw` บอกว่า *ตอนนี้* ใครถืออยู่ — เป็นสถานะปัจจุบัน ไม่ใช่ประวัติ

ผลพลอยได้: `ช้ากว่าแผนเดิม N วัน` ระดับเฟสที่ทำไว้ กลายเป็นการวัด **การเลื่อนของ Sign Off จริง**
แทนที่จะเป็นวันจบอะไรก็ไม่รู้

**ไม่ยกโมเดลคอลัมน์ V.1/V.2 มาใช้** เพราะงานย่อยในระบบมีช่วงเวลาจริง
(`CIVIL Review 11/08–02/09` · `PS GLOBAL UPDATE 02/09–10/09`) ซึ่งเป็นสิ่งที่ Gantt ทำได้ดี
สเปรดชีตย่อรอบพวกนี้ให้เหลือคอลัมน์เพราะ Excel วาดไทม์ไลน์ไม่ได้ ไม่ได้แปลว่าโมเดลคอลัมน์ดีกว่า

## 1 · Sign Off = TBD

`setPIDate(pid,'e','')` เว้นว่างได้แล้ว → เก็บ `d.e=''`

**ไม่ต้องเพิ่มฟิลด์ธง** เพราะ `piSpan()` รองรับอยู่ก่อนแล้ว — ถ้างานไม่มีวันจบของตัวเอง
มันถอยไปใช้ขอบเขตของงานย่อยแทน บาร์จึงยังวาดได้ปกติ

อนุญาตเฉพาะ **วันสิ้นสุด** เท่านั้น วันเริ่มยังบังคับ เพราะถ้าหายไปจะไม่มีจุดอ้างอิงให้วาดบาร์เลย

| | บาร์ | หน้ารายละเอียด |
|---|---|---|
| มีกำหนด | ขอบขวาทึบ มุมมน | — |
| TBD | **ขอบขวาเส้นประ 2px มุมไม่มน** + ชิป `TBD` | `ยังไม่กำหนดวัน Sign Off — บาร์ในผังใช้ขอบเขตของงานย่อยแทน` |

ช่องวันสิ้นสุดของงานที่มีงานย่อยจะขึ้นป้ายว่า **`วันสิ้นสุด · Target Sign Off`**
และ placeholder เปลี่ยนเป็น `เว้นว่าง = TBD` ให้รู้ว่าเว้นได้

### หัวลูกศรที่ถอดออก

แบบแรกใส่หัวลูกศรที่ปลายบาร์ (`::after` ที่ `right:-10px`) เพื่อสื่อว่า "ไปต่อ ไม่รู้จบเมื่อไหร่"
**วัดแล้วมองไม่เห็นจริง — ชื่องานล้นเลยขอบบาร์ออกมา 35px ทับตำแหน่งลูกศรพอดี**

เนื้อหาในบาร์ของแอปนี้ตั้งใจให้ล้นออกนอกบาร์ได้ (ชิปสถานะก็ล้น) ตัวบอกที่ผูกกับ *ขอบ* บาร์
จึงใช้ไม่ได้ ตัวบอกจริงต้องอยู่ใน *สายตา* คือชิป `TBD` ในบาร์ ส่วนเส้นประเป็นตัวเสริม

## 2 · งานย่อยเลยวัน Sign Off

ที่ตกลงกันไว้คือ **วันของงานแม่ชนะเสมอ** ระบบจึงปล่อยให้งานย่อยล้นออกนอกบาร์แม่โดยไม่ค้าน

แต่เมื่อ `d.e` ของแม่ = Sign Off จริง กรณีนี้แปลว่า **Sign Off จะไม่ทันแน่นอน** ต้องเตือน

```
เลย Sign Off 10 วัน
```

คำนวณเฉพาะงานที่มีงานย่อยและมีวันจบของตัวเอง จาก `max(piSpan(ลูก).e) − piDate(d.e)`
ขึ้นทั้งบนบาร์และในหน้ารายละเอียด

**ใช้สีแดงแบบเดียวกับ `.g-phwarn`** ที่เตือนงานล้นกรอบเฟสอยู่แล้ว — เป็นความหมายเดียวกัน
คนละระดับ ไม่ใช่การเพิ่มความหมายใหม่ให้สี

## ไม่ทำ

- ไม่เพิ่มฟิลด์ `V.1 Target` / `V.2 Target` / `Version.1 status` — งานย่อยทำหน้าที่นี้อยู่แล้ว
- ไม่เพิ่ม `Progress` แบบกรอกเอง — ระบบคิดจากงานย่อยและสถานะ ถ้าจะให้กรอกเองต้องคุยกันก่อน
  ว่าจะให้ค่าไหนชนะ
- ไม่แตะ Action Items · Automation Gantt · ชั้น persistence
- ไม่ย้ายข้อมูลเดิม — งานที่มีวันจบอยู่แล้วไม่เปลี่ยนอะไร

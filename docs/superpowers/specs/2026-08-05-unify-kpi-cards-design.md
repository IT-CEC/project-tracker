# รวมการ์ด KPI ทั้งแอปให้เป็นแพทเทิร์นเดียว

**วันที่:** 2026-08-05
**ขอบเขต:** `index.html` — การ์ดตัวชี้วัดทุกหน้า
**ต่อจาก:** [2026-08-04-typography-scale-design.md](2026-08-04-typography-scale-design.md)

## ปัญหา

รอบก่อนแก้การ์ดไปแค่ 2 หน้า (รายการงาน · รายงาน 3 ระดับ) อีก 4 หน้ายังเป็นของเดิม ผลคือแอปมีการ์ด **5 ระบบ 25 ใบ** ที่พูดกันคนละภาษา

| ระบบ | ที่ | ใบ | ป้าย | ค่า | ไอคอน | สูง |
|---|---|---|---|---|---|---|
| `.mkpi` | รายการงาน(5) · รายงาน(4) | 9 | 13/600 `--ink` | 28/700 | ✗ | 86–92 |
| `.pjcard` | แผนงาน(4) · ความต้องการ(3) | 7 | 11/600 `--ink3` | 20/700 | ✗ | 100 |
| `.kpi` | ภาพรวม | 3 | 13/500 `--ink2` | 24/700 | ✗ | 160 |
| `.kpi3` | Automation FTE · Timeline | 3 | 11/600 `--ink3` | 24/700 | ✓ 40px | 109 |
| `.ckcard` | ภาพรวม (cockpit) | 3 | — | — | — | ใหญ่พิเศษ |
| `.fgc` | **ไม่มีใครใช้** | 0 | | | | |

**จุดที่ขัดกันชัดสุดคือป้าย** — `.mkpi` ให้ป้ายเป็นตัวนำ (13px เข้ม) อีกสามระบบให้ป้ายจางแล้วให้ตัวเลขนำ ซึ่งคือ "ลำดับกลับหัว" ที่วิเคราะห์ไว้รอบก่อนและแก้ไปแค่สองหน้า

## วิธีที่เลือก — รวมที่ CSS ไม่แตะ markup

**ไม่** เขียน emitter ทั้ง 4 ตัวใหม่ให้ปล่อย markup `.mkpi` เพราะแต่ละตัวมีของเฉพาะตัว (`.dots` affordance บนภาพรวม · `--sc` + `onclick` + `.on` บนความต้องการ · `--kc` + `.k3unit` บน Automation) การรื้อ markup เสี่ยงเกินความจำเป็นสำหรับงานที่เป็นเรื่องหน้าตาล้วน ๆ

แทนที่ด้วยการให้ selector ทั้งหมด **ใช้กฎเดียวกันร่วมกัน** (grouped selector) — หนึ่งกฎต่อหนึ่งบทบาท แก้ที่เดียวมีผลทุกที่ ได้ผลเท่ากันโดยไม่แตะ JS

```css
.mkpi,.pjcard,.kpi,.kpi3                          → เปลือกการ์ด
.mkpi-lab,.pjcard .pjk,.kpi .kh,.kpi3 .k3lab      → ป้าย
.mkpi-val,.pjcard .pjv,.kpi .v,.kpi3 .k3val       → ค่า
.mkpi-cap,.pjcard .pjs,.kpi .chip,.kpi3 .k3sub    → คำอธิบาย
```

## แพทเทิร์น

### แกนที่เหมือนกันทุกใบ
```
เปลือก   : --surface · 1px --line · radius 16 · padding 14/16 · --cardsh
ป้าย     : 13/600 --ink        ← ป้ายเป็นตัวนำทุกที่
ค่า      : 28/700 tabular-nums
คำอธิบาย : 11/400 --ink3
```

### 3 ตัวแปร — มีเหตุผลรองรับ

**A · ค่าเป็นตัวเลข** (ค่าเริ่มต้น 28px) — รายการงาน · รายงาน · ความต้องการ · ภาพรวม

**B · ค่าเป็นข้อความยาว** → `#projRibbon .pjcard .pjv{font-size:20px}`
เฉพาะ **แผนงาน** เพราะค่าคือ `Solution Definition (BRD)` · `BRD Sign-off` ถ้าใช้ 28px จะตัดบรรทัดเละ
(`#reqKbar .pjcard .pjv` คงที่ 28px เพราะค่าที่นั่นเป็นตัวเลข — คลาสเดียวกันแต่คนละชนิดข้อมูล จึงต้องแยกด้วย id ของ container)

**C · มีไอคอน + วางแนวนอน** — `.kpi3` คงโครงเดิม (icon 40px + body ขวา)
เพราะการ์ดอยู่ในคอลัมน์กว้าง 240px ที่ `.brtoprow` บังคับไว้ แนวตั้งจะสูงเกิน และ 3 ใบนั้นเป็นของ *คนละชนิด* (กระบวนการ / FTE / ชั่วโมง) ไอคอนช่วยแยกได้จริง

> **กติกาไอคอน:** ใส่เมื่อการ์ดในแถวเป็นของคนละชนิด · ไม่ใส่เมื่อเป็นตัวแปรของสิ่งเดียวกัน — เหตุผลเดียวกับที่ตัดออกจากหน้ารายงาน (4 ใบเป็นระดับของสิ่งเดียวกัน ไอคอนไม่ได้บอกว่าใบไหนคือระดับไหน)

### แก้เพิ่มเติมที่จำเป็น

- **`.kpi .chip`** ปัจจุบันเป็น pill มีพื้นหลัง → ถอดพื้นหลังให้เป็นข้อความธรรมดาเหมือน caption ใบอื่น
- **`.pjcard`** มี `justify-content:center` + `min-height:100px` ทำให้เนื้อหาลอยกลางใบ → เปลี่ยนเป็นชิดบนเหมือนใบอื่น ให้ทุกใบเริ่มที่ระดับเดียวกัน
- **ลบ `.fgc` ทั้ง 6 กฎ** — ไม่มีหน้าไหน render

## นอกขอบเขต

**`.ckcard` 3 ใบบนภาพรวม** — ไม่ใช่การ์ด KPI มีลิสต์ความเสี่ยงกดได้และช่องกรอกค่า FTE อยู่ข้างใน เป็นคนละ component

ไม่แตะ JS · ไม่แตะ markup · ไม่แตะสีของค่า (`--sc` / `--kc` / `style="color:"` ยังทำงานเหมือนเดิม)

## ผลลัพธ์

22 จาก 25 ใบใช้ภาษาเดียวกัน · กฎหน้าตาการ์ดรวมเหลือ 4 กฎ (เปลือก/ป้าย/ค่า/คำอธิบาย) + 3 override · ลบโค้ดตาย 6 กฎ

## ความเสี่ยง

แตะ 4 หน้าที่ยังไม่เคยแตะ ตัวอักษรป้ายโตขึ้น (11→13px) และค่าบางที่โตขึ้น (20/24→28px) อาจทำให้ล้นหรือตัดบรรทัด จุดเสี่ยงสุด:
- `.kpi3` ในคอลัมน์ 240px — ค่า 28px + หน่วย + ไอคอน 40px อาจไม่พอ
- `.pjcard` บนแผนงาน — ป้าย 13px อาจดันความสูงเกิน `min-height:100px`
- `.kpi` บนภาพรวม — สูง 160px ถูกบังคับโดย `.toprow` ให้เท่ากับ cockpit

## การตรวจสอบ

1. `node --check` → `SYNTAX OK`
2. ทุกหน้า light + dark: 4 panel × sub-view ทั้งหมด ไม่มี JS error · topbar ไม่ล้นที่ 1280px
3. **ไม่มี element ใดล้นกรอบ** (ยกเว้น native `<select>` ที่ซ่อนอยู่หลัง custom dropdown ซึ่งเป็น false positive)
4. วัดการ์ดทุกระบบ — เปลือก/ป้าย/ค่า/คำอธิบาย ต้องได้ค่าเดียวกัน ยกเว้น override ที่ระบุไว้
5. เทียบภาพก่อน-หลังทุกหน้า รายงานจุดที่ layout ขยับจริง

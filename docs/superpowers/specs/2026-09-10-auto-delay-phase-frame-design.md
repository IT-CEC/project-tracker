# งานเลยกำหนดดีดเป็นล่าช้าเอง และการ์ดเฟสตัดสินจากกรอบเฟส

**วันที่:** 2026-09-10
**ขอบเขต:** `index.html` — งานใน Gantt แผนงานโครงการ + การ์ด Current Phase / Phase Status

## ที่มา

ผู้ใช้ขอ 3 อย่างพร้อมกัน

1. งานย่อยที่กำหนด due ไว้ ถ้าเลยกำหนดแล้วให้ **ดีดเป็น Delayed เอง** ไม่ต้องรอคนมากด
2. แต่ **ห้ามให้สถานะของงานไปเปลี่ยนการ์ด** Phase Status / Current Phase เพราะเป็นแค่งานย่อย
3. การ์ดจะเป็นล่าช้า **ก็ต่อเมื่องานในเฟสนั้นเกินวันที่ที่ตั้งไว้ให้เฟส** เพราะเฟสมี timeline แยกอยู่แล้ว

ข้อ 3 ทำให้ข้อ 2 เกิดขึ้นเอง — เมื่อการ์ดเลิกมองสถานะของงานโดยสิ้นเชิง ไม่ว่าสถานะจะมาจาก
คนกดหรือระบบดีดให้ ก็ไม่มีทางกระทบการ์ด

## 1 · สถานะที่ใช้แสดงผล

```js
piIsOverdue(d)  // ยังไม่เสร็จ · ไม่ได้พักไว้ · มีวันจบ · วันจบผ่านไปแล้ว
piEffSt(d)      // เลยกำหนด → 'Delayed' · ลูกคนใดเลยกำหนด → แม่ 'Delayed' · ไม่งั้นใช้ d.st
```

**คิดตอนแสดงผล ไม่เขียนทับ `d.st`** ข้อดีที่ตามมา

- ไม่มีการเขียน Firestore เลย ไม่ต้อง migrate ข้อมูลเดิม
- พอเลื่อนกำหนดออกไปหรือกดเสร็จ **มันกลับเป็นสถานะเดิมเอง** ไม่มีค่าค้าง
- คนสองคนเปิดพร้อมกันไม่แย่งกันเขียน

### ไม่ดีดให้ในกรณีเหล่านี้

| สถานะ | เหตุผล |
|---|---|
| `Completed` | เสร็จแล้ว จบ |
| `On Hold` | พักไว้โดยตั้งใจ ทุกคนรู้อยู่แล้วว่าหยุด การดีดเป็นล่าช้าไม่ได้บอกอะไรใหม่ |
| ไม่มีวันจบ (TBD) | ไม่มีกำหนดให้เลย จึงเลยกำหนดไม่ได้ |

### ห้ามเอาไปใช้ใน piCalcProg

`Not Started` = 0% แต่ `Delayed` = 50% ถ้าใช้สถานะที่แสดงผลไปคิดความคืบหน้า
**งานที่เลยกำหนดจะทำให้ progress เด้งขึ้นเอง** ซึ่งตรงข้ามกับความจริง

`piCalcProg` จึงยังใช้ `d.st` ดิบ — ตรวจแล้ว งาน Not Started ที่เลยกำหนด 9 วัน
แสดงเป็น Delayed แต่ progress ยังเป็น 0%

### จุดที่ใช้

สีแถบ · ป้ายสถานะบนแถบ · สีหัวเฟส (`piPhRoll`) — ทั้งหมดเป็นการแสดงผล
**ไม่แตะ `piRollStatus()`** ซึ่งเป็นตัวเขียน `p.st` ลงข้อมูลจริง

## 2 · ช่วงวันของเฟส

```js
piPhaseRange(ph) → {a, b, man, over}
```

ใช้วันที่ที่ตั้งไว้เองก่อน (`PH_STORE`) ถ้าไม่ได้ตั้งค่อยคิดจากขอบเขตงาน —
**กติกาเดียวกับที่ผัง Gantt ใช้อยู่แล้ว** (`_man` / `_pa` / `_pb` / `_sr`) จะได้ไม่มีทางเห็นไม่ตรงกัน

`over` = งานจบช้ากว่าวันจบของเฟสกี่วัน เกิดได้เฉพาะเฟสที่ตั้งวันเอง
เพราะถ้าคิดจากขอบเขตงาน งานย่อมไม่มีทางล้นกรอบตัวเอง

เดิมการ์ดคิด `phs` จากขอบเขตงานล้วนๆ **ไม่รู้จัก `PH_STORE` เลย**

## 3 · เกณฑ์ใหม่ของการ์ด

```
progress 100%              → เสร็จแล้ว
วันนี้ > วันจบเฟส            → ล่าช้า · เลยกำหนด N วัน
งานจบเลยวันจบเฟส (over>0)   → ล่าช้า · มีงานเกินกรอบเฟส N วัน     ← เกณฑ์ใหม่
วันนี้ < วันเริ่มเฟส          → ยังไม่เริ่ม
ไม่งั้น                     → เทียบ progress กับแผน → ตามแผน / เสี่ยง
```

**ตัดเกณฑ์ "มีงานสถานะ Delayed" ออกทั้งหมด** — นั่นคือทางที่สถานะของงานลามมาถึงการ์ด

เกณฑ์ `over` ตรงกับ `เกิน N วัน` สีแดงที่ผัง Gantt แสดงอยู่แล้ว การ์ดกับผังจึงพูดเรื่องเดียวกัน

## 4 · บั๊กที่เจอระหว่างทาง — วันที่เฟสหายหลังบันทึก

ผู้ใช้รายงานว่าตั้งวันที่เฟสแล้วกดเข้าไปดูใหม่เป็นช่องว่าง

`loadPhases()` และ `subscribePhases()` ประกอบ object ใหม่จาก **4 ฟิลด์เท่านั้น**

```js
m[d.key]={key:d.key,name:d.name,color:d.color||'#888',order:(d.order!=null?d.order:9999)};
//                                                    ไม่มี s / e
```

`piPhSave()` บันทึกทั้งอ็อบเจกต์ **ข้อมูลจึงอยู่ใน Firestore ครบมาตลอด** แต่พอ snapshot
กลับเข้ามา `PH_STORE` ถูกสร้างใหม่โดยไม่มี `s`/`e` — ค่าหายจากหน่วยความจำทันทีที่บันทึก

แก้ด้วย `phNorm(d)` ที่ **เก็บทุกฟิลด์ที่ได้มา แล้วค่อยเติม default เฉพาะตัวที่จำเป็น**
ฟิลด์ที่เพิ่มทีหลังจะไม่หายซ้ำรอยเดิม (`_key` เป็นของชั้น DB ไม่ใช่ข้อมูล จึงไม่เก็บกลับลงไป)

**บั๊กนี้ทำให้ข้อ 3 ใช้ไม่ได้เลย** ถ้าไม่แก้ — เพราะการ์ดใหม่พึ่งพาวันที่ของเฟสเป็นหลัก

## ไม่ทำ

- ไม่เขียนสถานะ `Delayed` ลงข้อมูลจริง — ดูเหตุผลข้อ 1
- ไม่แตะ `piRollStatus()` ที่เขียน `p.st`
- ไม่แตะ Action Items · Automation ribbon · ชั้น persistence

## การตรวจสอบ

1. งาน In Progress เลยกำหนด 5 วัน → แสดง `Delayed` แต่ `d.st` ยังเป็น `In Progress`
2. เลื่อนกำหนดออกไป → กลับเป็น `In Progress` เอง
3. `On Hold` · `Completed` · ไม่มีวันจบ → ไม่ดีดให้
4. `Not Started` เลยกำหนด 9 วัน → แสดง `Delayed` แต่ `piCalcProg` ยัง `0%`
5. ตั้ง 5 งานเป็น Delayed → **การ์ดไม่ขยับ** · ตั้งงานเลยกำหนดทั้งเฟส → **การ์ดยังไม่ขยับ**
6. งานจบเกินวันจบเฟส 15 วัน → การ์ดขึ้น `ล่าช้า · มีงานเกินกรอบเฟส 15 วัน`
7. `phNorm()` คืน `s`/`e` ครบและตัด `_key` ออก
8. regression #46–#71 ผ่านครบ · ไม่มี JS error · **`DB.saveItem` ถูกเรียก 0 ครั้ง**

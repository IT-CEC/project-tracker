# In Review ในตาราง Tracking (Action Items)

**วันที่:** 2026-08-06
**ขอบเขต:** `index.html` — ชุดสถานะของ Action Items
**เกี่ยวข้อง:** [2026-08-06-in-review-status-design.md](2026-08-06-in-review-status-design.md) (In Review ของ Gantt)

## สิ่งที่ผู้ใช้ขอ

เพิ่มสถานะ `In Review` ในตาราง Tracking และกำหนดได้ว่าเป็นฝั่ง Civil หรือ PS Global "เหมือนที่ทำให้ Gantt"

## วิเคราะห์ — ตารางนี้ต้องทำคนละแบบกับ Gantt

ผลลัพธ์ที่ผู้ใช้ต้องการเหมือนกัน แต่**โมเดลข้อมูลต่างกัน** วิธีจึงต่างกัน

| | Gantt (PI tasks) | Tracking (Action Items) |
|---|---|---|
| จำนวนช่องสถานะต่องาน | **1** (`st`) | **2** (`status` = Civil · `status2` = PS Global) |
| สองฝั่งทำงานยังไง | ส่งต่อกัน ทีละฝั่ง | คู่ขนาน ต่างฝ่ายต่างมีสถานะ |
| ต้องรู้ว่า "ค้างที่ใคร" ยังไง | ต้องเพิ่มฟิลด์ `rvw` | **คอลัมน์บอกอยู่แล้ว** |

Gantt ต้องเพิ่มฟิลด์ `rvw` เพราะสถานะมีช่องเดียว ถ้าไม่บันทึกไว้ก็ไม่มีทางรู้ว่าใครถือ

ตาราง Tracking มีคอลัมน์ `CIVIL WORK STATUS` กับ `PS GLOBAL WORK STATUS` แยกกันอยู่แล้ว (เห็นได้จากแถวที่ Civil เป็น `Done` แต่ PS Global ยัง `Not Started`) **การแบ่งฝั่งจึงถูกเข้ารหัสไว้ในตัวคอลัมน์** แค่เพิ่มค่าใหม่เข้าชุดสถานะ ก็ตั้ง In Review แยกฝั่งได้ทันที

**ถ้าเพิ่มฟิลด์ "ฝั่งไหน" แบบ Gantt ที่นี่จะซ้ำซ้อนและขัดแย้งกันเองได้** — ถ้าคอลัมน์ Civil บอก `In Review` แต่ฟิลด์ฝั่งบอก `PS Global` ระบบต้องเชื่ออันไหน ไม่มีคำตอบที่ถูก จึงไม่ทำ

## สิ่งที่ทำ

### 1 · เพิ่มค่าในชุดสถานะ

```
Not Started → In Process → In Review → On Hold → Done
                             ↑ แทรกใหม่
```

`ACT_SC['In Review'] = '#0071e3'` — น้ำเงินเดียวกับที่ใช้ใน Gantt เพื่อให้ทั้งสองหน้าสื่อความหมายเดียวกันด้วยสีเดียวกัน

ตำแหน่งต่อจาก `In Process` ตรงกับที่ทำใน Gantt (ต่อจาก In Progress) โดย `On Hold` ยังเป็นสถานะข้อยกเว้นอยู่ท้าย

> ชุดคำของตารางนี้ต่างจาก Gantt อยู่แล้ว — ใช้ `In Process` ไม่ใช่ `In Progress` และ `Done` ไม่ใช่ `Completed` **ไม่แตะของเดิม** เพิ่มเฉพาะ `In Review` ซึ่งอ่านเข้ากันได้กับทั้งสองชุด

### 2 · การ์ด KPI ใบใหม่

แถบบนเพิ่มจาก 5 เป็น 6 ใบ วางระหว่าง `NOT STARTED` กับ `DONE` ตามลำดับของสายงาน

```
TOTAL │ IN PROCESS │ NOT STARTED │ IN REVIEW │ DONE │ OVERDUE
                                  2 Civil
                                  5 PS Global
```

ใช้ `pair('In Review')` ซึ่งเป็นฟังก์ชันเดิมที่การ์ดอื่นใช้อยู่ จึงได้ทั้งการนับแยกฝั่งและ**การกดเพื่อกรอง**มาเองโดยไม่ต้องเขียนเพิ่ม

นี่คือสิ่งที่เทียบเท่ากับ `Civil n · PS n` บนหัวคอลัมน์ของบอร์ด Gantt — เห็นคิวรอตรวจของแต่ละฝั่งโดยไม่ต้องเลื่อนหา

> `On Hold` ไม่มีการ์ดและยังคงไม่มี — แถบ KPI เลือกแสดงเฉพาะสถานะที่ต้องติดตาม ไม่ได้แสดงครบทุกค่า

### 3 · สิ่งที่ได้มาเองโดยไม่ต้องแก้

**ตัวกรองทั้งสองฝั่ง** — `setOpts('actStatus', ACT_STATUS, …)` และ `setOpts('actStatus2', ACT_STATUS, …)` สร้างจากชุดสถานะโดยตรง

**ดรอปดาวน์ในตาราง** — `actStatusCell(a,f)` วนจาก `ACT_STATUS` เช่นกัน

**ตรรกะเลยกำหนด** — `actOverdue` / `actOverdue2` เคลียร์เฉพาะเมื่อเป็น `Done` งานที่ค้างรีวิวเลยกำหนดจึงยังนับว่าเลยกำหนด ซึ่งถูกต้องเพราะยังไม่จบ **ตั้งใจไม่แก้**

### 4 · ไม่ต้อง migrate

ไม่มีงานไหนถือค่าใหม่ และ `actNorm()` เติมค่าตั้งต้นเป็น `Not Started` ให้เฉพาะตอนที่ยังว่าง จึงไม่กระทบข้อมูลเดิม

## ไม่ทำ

- ไม่เพิ่มฟิลด์ "ฝั่งไหน" — คอลัมน์ทำหน้าที่นั้นอยู่แล้ว (เหตุผลด้านบน)
- ไม่แตะ `STATUS_LIST` ของ Gantt/Requirements/Bridge — คนละชุดคำศัพท์
- ไม่เปลี่ยนชื่อสถานะเดิม ไม่แตะตรรกะเลยกำหนด ไม่เพิ่มการ์ดให้ On Hold

## การตรวจสอบ

1. ดรอปดาวน์ในคอลัมน์ Civil และ PS Global มี `In Review` ทั้งคู่ และเลือกได้จริง
2. ตั้ง Civil เป็น `In Review` โดย PS Global ยังเป็นค่าอื่น — สองฝั่งเป็นอิสระต่อกันจริง
3. การ์ด `IN REVIEW` แสดงจำนวนแยกฝั่งตรงกับข้อมูล และกดแล้วกรองได้ทั้งสองฝั่ง
4. แถบ KPI เป็น 6 ใบ ไม่ล้นและไม่บีบจนอ่านไม่ออก
5. ตัวกรองสถานะทั้งสองอันมี `In Review`
6. งานที่เป็น `In Review` และเลยกำหนด ยังถูกนับใน `OVERDUE`
7. สีของ `In Review` เป็น `#0071e3` ตรงกับที่ใช้ใน Gantt
8. บันทึกลง Firestore แล้วอ่านกลับได้ (ทดสอบโดย stub `DB.saveItem` ตรวจ payload)
9. ไม่มี JS error · ทุก panel ยัง render ปกติทั้ง light/dark

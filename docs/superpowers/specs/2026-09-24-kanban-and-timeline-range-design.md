# 1 · บอร์ดสถานะ

## ปัญหา

วัดกับข้อมูลจริง 55 งาน

| | |
|---|---|
| ความสูงบอร์ดรวม | **2,551px = 2.8 หน้าจอ** |
| การ์ด 1 ใบ | 104px |
| `Completed` | **22 การ์ด · 2,543px** |
| `On Hold` / `Delayed` | 0 การ์ด แต่กินความกว้างคอลัมน์ละ 282px |

**`Completed` ใบเดียวกำหนดความสูงของทั้งบอร์ด** — 40% ของการ์ดเป็นงานที่จบไปแล้ว
ต้องเลื่อนผ่านทุกครั้งเพื่อดูงานที่ยังทำอยู่

และ `.kb{align-items:flex-start}` ปล่อยให้คอลัมน์ยืดตามจำนวนการ์ดแล้วให้ทั้งหน้าเลื่อน
พอเลื่อนลงไปดูการ์ดใบท้ายๆ **หัวคอลัมน์อื่นหายหมด** บอร์ดจึงไม่ทำหน้าที่เป็นบอร์ด

## สิ่งที่ทำ

### แต่ละคอลัมน์เลื่อนในตัวเอง

การ์ดย้ายไปอยู่ใน `.kcol-body` ที่มี `overflow-y:auto` ส่วนหัวคอลัมน์อยู่นอกกล่องนั้น
ความสูงบอร์ดตรึงที่ `calc(100vh - 310px)` — **หัวคอลัมน์กับตัวเลขเห็นตลอดเวลา**
เป็นแพทเทิร์นเดียวกับ Trello/Jira

### ตัด `Completed` ออกจากบอร์ด

`KB_STATUSES = STATUS_LIST.filter(x => x !== 'Completed')`

**แต่ไม่ตัดทิ้งเงียบๆ** — ขึ้นบรรทัดสรุปไว้เหนือบอร์ด ไม่งั้นจะดูเหมือนโปรเจคมีแค่ 33 งาน

```
เสร็จแล้ว 34 จาก 68 งาน — คอลัมน์ Completed ไม่แสดงบนบอร์ด    [ดูรายการที่เสร็จแล้ว]
```

ปุ่มพาไปแท็บ Full Details

### การ์ดกะทัดรัด

3 ชั้น → 2 ชั้น: ชื่องาน / (ชิปเฟส · ความสำคัญ · ฝั่งที่ตรวจ · ความคืบหน้า · วันครบกำหนด)

**ชิปเฟสย่อเหลือรหัส** (`02` แทน `02_Solution Definition (BRD)`) พร้อม tooltip ชื่อเต็ม —
รอบแรกยุบเป็น 2 ชั้นแล้วการ์ดยังสูง 95px เพราะชื่อเฟสเต็มกิน ~150px จาก 260px ที่มี
แถวจึงตัดบรรทัดแล้วกลับไปเป็น 2 บรรทัดเหมือนเดิม พอย่อชิปถึงได้ **67px จริง**

แสดงเฉพาะวันครบกำหนด ไม่แสดงวันเริ่ม — บนบอร์ดสถานะ สิ่งที่ต้องรู้คือ "ครบเมื่อไหร่"

### คอลัมน์ว่างยุบเป็นแถบแคบ

`.kcol.kempty{width:128px}` — ยังบอกว่า "ไม่มีงานติดอยู่" ซึ่งเป็นข้อมูล
แต่ไม่กินความกว้างเท่าคอลัมน์ที่มีของจริง คืนความกว้างมา ~300px

# 2 · แกนเวลาของผัง Gantt

## ปัญหา

ผู้ใช้รายงานว่ากรองเฟสแล้ว "เดือนตุลา/พฤศจิกาหายไป"

```js
var dts=[]; rows.forEach(...)            // rows = เฉพาะงานที่ผ่านตัวกรอง
var base = new Date(y, minD.getMonth()-1, 1);
var endP = new Date(y, maxD.getMonth()+1, 0);
```

**ช่วงเวลาคิดจากงานที่ผ่านตัวกรองเท่านั้น** กรองเฟส 02 ซึ่งกิน `16/06 → 30/09`
ผังก็เหลือ May–September — เดือนไม่ได้หาย แต่ไม่มีงานของเฟสนั้นอยู่ในเดือนนั้น

### ของแถม: ระยะเผื่อไม่สมมาตร

`new Date(y, m+1, 0)` = **วันสุดท้ายของเดือน m** ไม่ใช่ m+1 เพราะ `day 0` หักกลับไปหนึ่งเดือน

```
new Date(2026, 9, 0)   →  30 ก.ย.   ที่ได้จริง
new Date(2026, 10, 0)  →  31 ต.ค.   ที่โค้ดตั้งใจ
```

ผังจึงมีที่ว่างหน้า 1 เดือน **ท้าย 0 เดือน** แถบงานตัวสุดท้ายชนขอบขวาพอดี

## สิ่งที่ทำ

**ช่วงเวลาคิดจากงานทั้งหมด** (`PI_STORE[GCTX]`) ไม่ใช่ `filteredPI()` และรวมวันที่ของเฟส
ที่ตั้งเอง (`piPhaseRange`) ด้วย ไม่งั้นเฟสที่กรอบกว้างกว่างานข้างในจะถูกตัดท้าย

ใช้ `piSpan(d)` แทน `d.s`/`d.e` ดิบ — งานแม่ที่ยังไม่กำหนดวันจบ (TBD) จะได้นับขอบเขตจากงานย่อย

แก้ `endP` เป็น `new Date(y, m+2, 0)` ให้เผื่อท้ายจริง 1 เดือน

**ปุ่มเลื่อนยังพาไปที่งานที่กรองอยู่** — `firstx` คิดจาก `rows` (งานที่กรอง) ไม่ใช่ต้นโครงการ
แกนเวลาเต็มช่วงแต่ไม่ต้องเลื่อนหาเอง

## ทำไมเลือกคงช่วงเต็ม

ผู้ใช้เลือกเอง เหตุผลที่แนะนำ: **ตัวกรองควรเปลี่ยน "แถวไหนแสดง" ไม่ใช่ "หน้าต่างเวลา"**
แกนคงที่ทำให้เทียบข้ามเฟสได้ ตำแหน่งแถบไม่ขยับ เส้นวันนี้อยู่ที่เดิม
และเห็นว่าเฟสที่กำลังดูอยู่ตรงไหนของทั้งโครงการ

## ผล

กรองหรือไม่กรองก็ได้ **32 เดือนเท่ากัน** (`April 2026 … November 2028`)
ก่อนแก้จบที่ October 2028 — เดือนเผื่อท้ายกลับมาแล้ว

## ไม่ทำ

- ไม่แตะบอร์ด Priority นอกจาก CSS ที่ใช้ร่วมกัน (ยังครบ 4 คอลัมน์)
- ไม่ตัดชื่องานยาวให้สั้นลง — การ์ดที่ชื่อยาวยังสูงกว่า 67px ซึ่งยอมรับได้
- ไม่เลื่อนผังอัตโนมัติไปหาเฟสที่กรอง (ผู้ใช้เลือกทางที่ไม่มีอันนี้)

## การตรวจสอบ

1. บอร์ด: สูง 590px · การ์ด 67px · `overflow-y:auto` ต่อคอลัมน์ · คอลัมน์ว่าง 128px
2. บรรทัดสรุปขึ้น `เสร็จแล้ว 34 จาก 68 งาน` และไม่มีคอลัมน์ Completed
3. บอร์ด Priority ยังครบ 4 คอลัมน์
4. **แกนเวลา: ไม่กรอง 32 เดือน · กรองเฟส 02 ก็ 32 เดือน เหมือนกันทุกตัวอักษร**
5. ป้ายเดือนไม่ล้นกล่องทั้ง 8 ระดับซูม
6. ทุก panel เปิดได้ · สิทธิ์สองระดับยังทำงาน (ผู้ดูอย่างเดียวเขียน 0 ครั้ง)
7. ไม่มี JS error · ไม่มีไฟล์โหลดไม่สำเร็จ · เขียน Firestore 0 ครั้งตลอดการทดสอบ

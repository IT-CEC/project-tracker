# สองระดับสิทธิ์ — ผู้ดูแล IT แก้ได้ คนอื่นดูอย่างเดียว

**วันที่:** 2026-09-11
**ขอบเขต:** `firestore.rules` · `js/auth.js` · `js/firebase-config.js` · `index.html`

## ที่มา

ต้องการให้แผนงานโครงการและ Automation แก้ได้เฉพาะ IT ส่วนคนอื่นดูอย่างเดียว
โดยแยกจาก "รหัสที่ใช้เข้า" — `admin2026` ได้สิทธิ์เต็ม `civil2026` ดูอย่างเดียว

## ข้อจำกัดที่กำหนดรูปการออกแบบ

**Firebase ผูกรหัสผ่านกับบัญชี หนึ่งบัญชีมีรหัสเดียว** จะมีสองรหัสจึงต้องมีสองบัญชี

```
admin@civil.co.th  / admin2026   →  แก้แผนงานโครงการและ Automation ได้
team@civil.co.th   / civil2026   →  ดูอย่างเดียวสำหรับสองส่วนนั้น
```

**ห้ามเช็ครหัสในฝั่งหน้าเว็บ** — `if(pass==='admin2026') canEdit=true` ใครกด F12
พิมพ์ `canEdit=true` ก็แก้ได้ หรือเรียก `DB.saveItem()` ตรงๆ ข้ามหน้าจอไปเลย
นั่นคือความปลอดภัยปลอม

ของจริงบังคับที่ `firestore.rules` ซึ่งทำงานบนเซิร์ฟเวอร์ของ Google

## กฎฝั่งเซิร์ฟเวอร์

| ล็อก (admin เท่านั้น) | เปิด (ทุกคนที่ล็อกอิน) |
|---|---|
| `pi_tasks` `pi_phases` | `requirements` `action_items` |
| `ap_tasks` `ap_groups` | `report_levels` `settings` |
| `bridge` `plan` | `audit_log` (เพิ่มได้อย่างเดียว) |

### ทำไมต้องตัด `match /{document=**}` ออก

**กฎ Firestore เป็น OR กัน ไม่ใช่การเขียนทับ** ถ้ามี catch-all ที่ให้ทุกคนเขียนได้
มันจะปลดล็อกทุกกฎที่เข้มกว่าข้างบนทันที — `pi_tasks` จะกลับมาแก้ได้ทุกคน
ทั้งที่กฎข้างบนดูเหมือนยังอยู่ **นี่เป็นกับดักที่มองไม่เห็นจากการอ่านไฟล์ผ่านๆ**

ข้อแลกเปลี่ยน: collection ที่ไม่ได้เขียนถึงจะถูกปฏิเสธทั้งอ่านและเขียน
เพิ่ม collection ใหม่เมื่อไหร่ต้องมาเพิ่มที่นี่ด้วย ปัจจุบันมี 11 ตัว ครบแล้ว

### ของแถม: `audit_log` ลบไม่ได้แม้แต่ admin

```js
match /audit_log/{id} { allow read, create: if signedIn(); allow update, delete: if false; }
```

ปิดช่องโหว่ที่เคยบอกไว้ตอนทำหน้าประวัติ ว่าคนลบร่องรอยของตัวเองได้

## หน้าล็อกอิน

ช่องกรอกยังมีช่องเดียวเหมือนเดิม — ลอง `team@` ก่อน (คนส่วนใหญ่) ถ้ารหัสไม่ตรง
ค่อยลอง `admin@` ผู้ใช้จึงไม่ต้องเลือกอะไรเพิ่ม ไม่รู้สึกว่าต่างจากเดิม

หยุดลองทันทีถ้า error ไม่ใช่ "รหัสผิด" (เน็ตหลุด บัญชีถูกระงับ ฯลฯ) เพื่อไม่ให้
ยิงซ้ำโดยไม่จำเป็น

`js/auth.js` นำเข้า config แบบ namespace (`import * as CFG`) เพราะถ้าเครื่องไหน
ยังไม่มี `ADMIN_EMAIL` การนำเข้าแบบระบุชื่อจะพังทั้งไฟล์

## ฝั่งหน้าจอ

`window.ERP_ROLE` ตั้งจาก **อีเมลที่ล็อกอินสำเร็จจริง** ไม่ใช่จากรหัสที่พิมพ์

| | ผู้ดูแล | ดูอย่างเดียว |
|---|---|---|
| ป้ายบนแถบหัว | — | `ดูอย่างเดียว` |
| ปุ่มเพิ่มเฟส/เพิ่มงาน/ลบ/ย้าย | เห็น | ซ่อน |
| ลากแถบใน Gantt | ได้ | ปิด (ซ่อนที่จับ) |
| ช่องกรอกในหน้ารายละเอียด | แก้ได้ | `disabled` ทั้งหมด |
| Requirements · ติดตามสถานะ · รายงาน | แก้ได้ | **แก้ได้ตามเดิม** |

ใส่ยาม `erpDenyEdit()` ไว้ 25 ฟังก์ชันที่เป็นทางเข้าของการแก้ — กดแล้วขึ้นข้อความ
บอกเหตุผลแทนที่จะเงียบหรือขึ้น error ดิบ

**ทั้งหมดนี้เป็นแค่ความสะดวก ไม่ใช่ความปลอดภัย** ถ้าใครแก้ `ERP_ROLE` ใน DevTools
ปุ่มจะกลับมา แต่เขียนไม่ผ่านอยู่ดีเพราะ rules ปฏิเสธ — และจะเห็นข้อความ
"ไม่มีสิทธิ์แก้ส่วนนี้" ซึ่งแยกจาก "เน็ตมีปัญหา" แล้ว

## ลำดับการติดตั้ง — ห้ามสลับ

โค้ดชุดนี้ **ห้าม deploy ก่อน** สองขั้นนี้ ไม่งั้นจะไม่มีใครแก้แผนงานได้เลย
เพราะ `ADMIN_EMAIL` ถูกตั้งไว้แล้วแต่บัญชียังไม่มีอยู่จริง

1. Firebase Console → Authentication → Users → **Add user**
   `admin@civil.co.th` / `admin2026`
2. Firebase Console → Firestore → Rules → วาง `firestore.rules` ใหม่ → **Publish**
3. แล้วค่อย deploy โค้ด

ถ้าอยากย้อนกลับ: ลบบรรทัด `export const ADMIN_EMAIL` ใน `js/firebase-config.js`
ระบบจะกลับไปเป็นทุกคนแก้ได้เหมือนเดิม (แต่ rules ยังล็อกอยู่ ต้องย้อน rules ด้วย)

## ไม่ทำ

- ไม่ทำสิทธิ์รายคน — ยังเป็นบัญชีร่วม 2 ใบ ไม่ใช่ 1 คน 1 บัญชี
  ถ้าต้องการรู้ว่า "ใคร" จริงๆ ต้องแยกบัญชีรายคน ซึ่ง Firebase Auth ฟรีอยู่แล้ว
- ไม่ล็อก Requirements / ติดตามสถานะ / รายงาน ตามที่ผู้ใช้เลือก
- ไม่แตะหน้าล็อกอินให้มีตัวเลือกบทบาท — ช่องเดียวเหมือนเดิม

## การตรวจสอบ

1. ผู้ดูแล: ไม่มีป้าย · ปุ่มครบ · ที่จับลากแถบมี · `setPIField` เขียนได้
2. ดูอย่างเดียว: ป้ายขึ้น · ปุ่มเพิ่มเฟส/เพิ่มงานหาย · ที่จับลากหาย
3. ดูอย่างเดียวกด `setPIField` `setPIDate` `piAddTask` `piDeleteTask` `piMoveTask`
   → **พยายามเขียน 0 ครั้ง และค่าเดิมไม่ถูกแตะ**
4. หน้ารายละเอียด: ช่องกรอก 12/12 ถูก `disabled` · ปุ่มเลื่อนกำหนดหาย
5. หน้าติดตามสถานะกับความต้องการ: ปุ่มเพิ่มยังอยู่ (ไม่ได้ล็อก)
6. Automation: ปุ่มเพิ่มรายการหาย
7. สลับกลับเป็นผู้ดูแล → แก้ได้อีกครั้ง
8. regression 10 ชุดผ่านครบ · ไม่มี JS error

**ยังตรวจไม่ได้ในเครื่อง:** กฎฝั่งเซิร์ฟเวอร์ ต้องทดสอบบนเว็บจริงหลังสร้างบัญชีและ
publish rules แล้ว โดยล็อกอินด้วย `civil2026` แล้วลองแก้แผนงาน — ต้องขึ้นว่าไม่มีสิทธิ์

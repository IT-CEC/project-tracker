# รายงาน 3 ระดับ — เปลี่ยน matrix เป็นการ์ดสรุป 4 ใบ

**วันที่:** 2026-08-04
**ขอบเขต:** ส่วนบนของ sub-view `#reportView` ใน `index.html` เท่านั้น
**ก่อนหน้า:** [2026-08-04-report-levels-design.md](2026-08-04-report-levels-design.md) §2 (matrix แผนก × ระดับ) — เอกสารนี้แทนที่หัวข้อนั้น

## เป้าหมาย

แทนที่ตาราง matrix แผนก × ระดับ (9 แถว × 4 คอลัมน์) ด้วยการ์ดสรุป 4 ใบ ให้ส่วนบนของหน้าอ่านง่ายขึ้นเวลาพรีเซ้น CEO

## เรื่องตัวเลขในภาพต้นทาง

ภาพการ์ดที่ผู้ใช้ส่งมาแสดง `Total 81 · Operational 32 · Managerial 37 · Executive 14` ซึ่งเป็นการ์ดสรุปใน Excel ที่คำนวณไว้ตอนไฟล์ยังมี 81 แถว **ไม่ใช่ค่าที่ต้อง hardcode** การ์ดในแอปคำนวณจากข้อมูลสดใน Firestore เสมอ ปัจจุบันจึงได้ `90 · 39 · 37 · 17`

(สังเกตว่าภาพต้นทางก็มีอาการนับซ้ำเหมือนกัน: 32+37+14 = 83 เกิน 81 อยู่ 2 — คือรายการที่ครอบคลุมหลายระดับชุดเดียวกับที่ระบบเราเจอ)

## 1. การ์ด

| การ์ด | ตัวเลข | สี | ปัจจุบัน |
|---|---|---|---|
| ทั้งหมด | `RPTS.length` (นับไม่ซ้ำ) | สีปกติ (`var(--ink)`) | 90 |
| Operational | จำนวนรายการที่ครอบระดับนี้ | `#0071e3` | 39 |
| Managerial | 〃 | `#ff9500` | 37 |
| Executive | 〃 | `#5e5ce6` | 17 |

**สีใช้ชุดเดิมของแอป (`RPT_LVC`) ไม่ใช่เขียว/ส้ม/น้ำเงินตามภาพต้นทาง** — เพราะ chip "ระดับ" ในตารางข้างล่างใช้ชุดนี้อยู่แล้ว ถ้าการ์ดใช้คนละชุด สีเดียวกันจะหมายถึงคนละระดับในหน้าเดียวกัน

**ตัวเลขบนการ์ดเป็นยอดรวมทั้งหมดเสมอ ไม่เปลี่ยนตาม filter** — การ์ดทำหน้าที่พาดหัว ส่วนตารางข้างล่างบอกว่ากำลังดูอะไรอยู่ (แพทเทิร์นเดียวกับ KPI ของหน้า Action Item ซึ่ง `renderActKpi` ก็นับจาก `ACTS` ทั้งชุด ไม่ใช่ผลลัพธ์ที่กรองแล้ว)

ใต้แถวการ์ดมีบรรทัดอธิบายว่าทำไมผลรวม 3 ระดับ (93) ไม่เท่าจำนวนรายงาน (90) — คำนวณจำนวนรายการที่ครอบหลายระดับจากข้อมูลจริง ไม่ hardcode

## 2. การคลิก

| คลิกที่ | ผลลัพธ์ |
|---|---|
| การ์ดระดับ | กรองระดับนั้น · กดซ้ำที่การ์ดเดิม = ยกเลิกตัวกรองระดับ |
| การ์ด "ทั้งหมด" | ล้างตัวกรองทุกตัว (เท่ากับปุ่ม "ล้าง") |

- การ์ดที่ active ได้คลาส `on` (ขอบสี accent + พื้น `--mint`)
- "ทั้งหมด" ถือว่า active เมื่อไม่มีตัวกรองระดับใดถูกเลือก
- **คลิกการ์ดแตะเฉพาะตัวกรองระดับ ไม่ไปล้างตัวกรองแผนก** — แผนกเป็นสิ่งที่ผู้ใช้เลือกเองจาก dropdown การไปล้างให้จะน่าประหลาดใจ (ต่างจาก matrix เดิมที่หัวคอลัมน์ล้างแผนกให้ เพราะตอนนั้น matrix เป็นตัวคุมทั้งสองแกน)

## 3. สิ่งที่หายไป

การแยกรายแผนกในส่วนบนหายไปทั้งหมด — ยังกรองรายแผนกได้จาก dropdown `แผนก` และคอลัมน์ `แผนก` ในตารางยังอยู่

## 4. โค้ด

**HTML** — แทน container เดิม
```html
<div class="tablecard" style="padding:14px 16px"><div class="tscroll"><div id="rptMatrix"></div></div></div>
```
ด้วย
```html
<div id="rptCards" class="actkpi"></div>
```

**CSS** — ลบบล็อก `.rptmx*` ทั้ง 12 บรรทัด · **คง `.mxnote` ไว้** (ใช้กับบรรทัดเชิงอรรถ) · เพิ่ม 1 บรรทัดสำหรับสถานะ active ของการ์ด:
```css
.actk.on{border-color:var(--accent);background:var(--mint)}
```
คลาส `.actk` / `.actk-v` / `.actk-l` / `.actk.clk` / `.actkpi` / `.actkrow` มีอยู่แล้วและรองรับ dark mode — ไม่ต้องเขียนใหม่

การเพิ่ม `.actk.on` ไม่กระทบหน้า Action Item เพราะการ์ดที่นั่นไม่เคยได้คลาส `on`

**JS**
- `renderRptMatrix()` → `renderRptCards()` (เปลี่ยนชื่อให้ตรงกับสิ่งที่มันทำ)
- `renderRpts()` เรียก `renderRptCards()` แทน
- เพิ่ม `rptPickLv(l)` — toggle เฉพาะตัวกรองระดับ
- `rptPick(d,l)` และ `rptClear()` คงเดิม ไม่แตะ

## นอกขอบเขต

ไม่แตะตาราง · filter dropdown · drawer · หน้าอื่น · sub-view อื่น

## การตรวจสอบ

1. `node --check` บนสคริปต์ก้อนหลัก → `SYNTAX OK`
2. Playwright (stub `DB.saveItem`/`deleteItem` ก่อน — หน้าเว็บต่อ Firestore จริง):
   - การ์ด 4 ใบ ค่า `90 / 39 / 37 / 17` และเชิงอรรถขึ้นเลข 93 กับ 90
   - `#rptMatrix` และ `table.rptmx` ไม่มีเหลือใน DOM
   - คลิกการ์ด `Managerial` → ตารางเหลือ 37 แถว การ์ดนั้นได้คลาส `on` · คลิกซ้ำ → กลับเป็น 90 แถว
   - เลือกแผนก `PM เครื่องจักร` จาก dropdown แล้วคลิกการ์ด `Executive` → ตารางเหลือ 6 แถว **และแผนกยังถูกเลือกอยู่**
   - คลิกการ์ด "ทั้งหมด" → ล้างทุกตัวกรอง กลับมา 90 แถว
   - ตัวเลขบนการ์ดไม่เปลี่ยนตลอดทุกขั้นข้างบน
3. ไม่ regression — 4 panel และ 4 project view render ปกติ ไม่มี JS error ใหม่ · KPI ของหน้า Action Item หน้าตาไม่เปลี่ยน

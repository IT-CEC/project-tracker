# ประวัติการใช้งาน — บันทึกว่าใครแก้อะไรเมื่อไหร่

**วันที่:** 2026-09-11
**ขอบเขต:** `js/db.js` · `js/auth.js` · `index.html` (หน้าตั้งค่า)

## ที่มา

ทุกคนในทีมแก้ข้อมูลเดียวกันได้หมด ต้องรู้ว่าใครแก้อะไรไว้บ้าง

## ข้อเท็จจริงที่กำหนดรูปการออกแบบ: เบราว์เซอร์อ่านชื่อเครื่องไม่ได้

ไม่มี API ไหนให้เว็บอ่านชื่อคอมพิวเตอร์ เป็นกำแพงความปลอดภัยระดับ OS
ถ้าเว็บอ่านได้ เว็บทุกเว็บในโลกก็อ่านได้เหมือนกัน

| อ่านได้ | ตัวอย่าง |
|---|---|
| ระบบปฏิบัติการ + เบราว์เซอร์ | `Windows 10/11 · Edge 131` |
| ❌ ชื่อเครื่อง | — |
| ❌ IP | ต้องมีเซิร์ฟเวอร์ ซึ่งโปรเจคนี้ไม่มี |

**ทางที่ใช้:** ถามครั้งเดียวตอนเข้าใช้ครั้งแรกของแต่ละเบราว์เซอร์ → เก็บใน
`localStorage.erp_device` → แนบไปกับทุก log · แก้ทีหลังได้ในหน้าตั้งค่า

ข้ามได้ ถ้าข้าม log จะขึ้นว่า `ไม่ระบุ` จนกว่าจะไปตั้ง — ไม่บล็อกการใช้งาน

### ข้อจำกัดที่เขียนไว้บนหน้านั้นเลย

> ชื่อเครื่องเป็นค่าที่ผู้ใช้ตั้งเอง ใช้เพื่อสืบย้อน ไม่ใช่การยืนยันตัวตน

ทุกคนล็อกอินด้วยบัญชี Firebase เดียวกัน (CLAUDE.md §5) ระบบจึงไม่มีตัวตนจริงให้ดึงตั้งแต่แรก
คนที่ตั้งใจเลี่ยงพิมพ์ชื่อปลอมหรือล้าง localStorage ได้ — และเพราะ `firestore.rules` อนุญาต
ให้ทุกคนที่ล็อกอินเขียนได้ทุก collection **คนที่ตั้งใจลบ log ของตัวเองก็ทำได้**

## ดักที่ชั้น DB ชั้นเดียว

`saveItem` / `updateItem` / `deleteItem` เป็นทางผ่านของการเขียนทุกอย่างในระบบ
ดักตรงนั้นได้ครบโดยไม่ต้องไล่แก้ทีละฟังก์ชันในแอป และไม่มีทางหลุด

### "ค่าก่อน" มาจากสำเนาในหน่วยความจำ

`db.js` เก็บ `_last[col][id]` จากผลของ `loadAll` และทุก snapshot ของ `subscribe`
พอจะเขียนก็เทียบกับสำเนานั้น — **ไม่ต้องอ่าน Firestore ก่อนเขียน** จึงไม่กินโควตาอ่าน
และไม่หน่วงการบันทึก

### กฎเหล็กสองข้อ

1. **log ต้องไม่ทำให้การบันทึกข้อมูลจริงพัง** — `_write()` เป็น fire-and-forget
   ครอบ try/catch และ `.catch(()=>{})` ทุกชั้น
2. **`audit_log` ต้องไม่เขียนผ่าน `saveItem`** — ใช้ `addDoc` ตรง และ `_audit()` ออกทันที
   ถ้า `col === AUDIT_COL` ไม่งั้นจะ log ตัวเองวนไม่จบ

โค้ด audit อยู่ **หลัง** `try/finally` ของการเขียนจริง ถ้า `setDoc` ล้มเหลวจะไม่มี log
— ไม่บันทึกสิ่งที่ไม่เกิดขึ้น

## โครงเอกสาร `audit_log/{auto}`

```js
{ ts: 1757577720000, at: '11/09/2026 16:22',
  who: 'IT_NATHIPAT', ua: 'Windows 10/11 · Edge 131',
  act: 'edit',                       // login · logout · add · edit · del
  col: 'pi_tasks', id: 'b12', name: 'BRD08 - Work Order',
  ch: [ {f:'e',  a:'18/09/2026',  b:'25/09/2026'},
        {f:'st', a:'In Progress', b:'Delayed'} ] }
```

### การเทียบค่า

- ข้าม `__docId` `updatedAt` `_key` `_pi` `_id` — ไม่ใช่ข้อมูลของผู้ใช้
- ค่าเดี่ยว → `ก่อน → หลัง` (ตัดที่ 80 ตัวอักษร)
- **array/object → สรุปเป็น `1 รายการ → 2 รายการ` ไม่ dump JSON** เพื่อกัน doc บวม
  (`dueLog` `log` `dep` `stages` มีของเยอะ)
- ถ้าเทียบแล้วไม่มีอะไรเปลี่ยน **ไม่บันทึก** — กัน log ขยะจากการ save ซ้ำ
- จำกัด 25 ช่องต่อรายการ

### ชื่อช่องแปลตอนแสดง ไม่แปลตอนเก็บ

`db.js` เก็บคีย์ดิบ (`e`, `st`) ส่วน `index.html` มี `FLD_TH` แปลเป็นไทยตอนแสดง —
`db.js` จึงไม่ต้องรู้จักฟิลด์ของแอปเลย เป็นตัวจัดการข้อมูลล้วนๆ ตามที่ CLAUDE.md วางไว้

## หน้าแสดงผล

อยู่ในหน้าตั้งค่า เมนู **ประวัติการใช้งาน** — ตาราง เวลา · เครื่อง · การกระทำ · รายการ · สิ่งที่เปลี่ยน
กรองตามเครื่อง/ประเภท/ค้นหาได้

### โควตา

| | |
|---|---|
| เขียน | +1 ต่อการบันทึก 1 ครั้ง (Spark 20,000/วัน) |
| อ่าน | **โหลดเมื่อเปิดแท็บเท่านั้น** 300 รายการล่าสุด ผ่าน `DB.loadRecent()` |

**ไม่ `subscribe`** — ถ้า subscribe ทุกเครื่องจะกินโควตาอ่านทุกครั้งที่มีใครแก้อะไรสักอย่าง
และหน้านี้ไม่ได้ต้องการ realtime มีปุ่มโหลดใหม่พอ

หน้าตั้งค่าจำกัดความกว้าง 880px ซึ่งบีบตารางจนคอลัมน์ "สิ่งที่เปลี่ยน" ตัดบรรทัดรัว
จึงขยายเป็น 1360px เฉพาะตอนเปิดแท็บนี้ด้วย `:has(#sec-audit.active)`

## ไม่ทำ

- ไม่ทำสิทธิ์แยกรายคน — บัญชีเดียวร่วมกัน ไม่มีตัวตนให้แยก
- ไม่แก้ `firestore.rules` ให้ `audit_log` ลบไม่ได้ — ทำได้ถ้าต้องการ แต่ไม่ได้ขอ
- ไม่ลบ log อัตโนมัติ — 1GB เก็บได้หลักล้านรายการ และการอ่านจำกัดที่ 300 อยู่แล้ว
- ไม่บันทึกการเปลี่ยนที่อยู่ใน localStorage (ธีม ภาษา การหุบเฟส) — เป็นความชอบส่วนตัว
  ไม่ใช่ข้อมูลร่วม

## การตรวจสอบ

1. `DB.setActor` / `DB.logEvent` / `DB.loadRecent` มีครบ
2. กล่องถามชื่อเครื่องเปิดตอนยังไม่เคยตั้ง · บันทึกแล้วเก็บลง localStorage · **ตั้งแล้วไม่ถามซ้ำ**
3. ทางเขียน log ไม่โยน error (ถ้าโยนจะลามไปทำให้การบันทึกข้อมูลจริงพัง)
4. `loadRecent` ตอนยังไม่ล็อกอินโยน error และ `renderAudit` ดักไว้ไม่ให้หน้าพัง
5. ตารางแสดงครบ 3 ประเภท (ลบ/แก้ไข/ล็อกอิน) · แปลชื่อช่องเป็นไทย · array สรุปเป็นจำนวนรายการ
6. กรองตามเครื่อง 3→2 แถว · ตามประเภท →1 แถว · ล้างแล้วกลับมา 3
7. regression #46–#75 ผ่านครบ · ไม่มี JS error · ไม่มีไฟล์โหลดไม่สำเร็จ

**ยังตรวจไม่ได้ในเครื่อง:** ทางเขียน log จริง (diff → `addDoc`) เพราะเครื่องทดสอบไม่ได้ล็อกอิน
Firestore จึงปฏิเสธทุกการเขียน ต้องยืนยันบนเว็บจริงหลัง deploy โดยเปิดหน้านี้แล้วดูว่ามีรายการ
ล็อกอินของตัวเองขึ้นหรือไม่

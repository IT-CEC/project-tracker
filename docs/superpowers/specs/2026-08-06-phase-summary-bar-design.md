# แถบสรุปช่วงเวลาบนแถวหัวเฟส (Gantt)

**วันที่:** 2026-08-06
**ขอบเขต:** `index.html` — แถวหัวเฟสใน `renderPIGantt()`

## สิ่งที่ผู้ใช้ขอ

แถวหัวเฟส เช่น `02_Solution Definition (BRD)` ตอนนี้มีแต่ป้ายชื่อ ไม่มีอะไรในแถบเวลา
อยากให้มีแถบคุมภาพใหญ่เพื่อเห็นไทม์ไลน์ของเฟสนั้น

**ข้อกำหนดจากผู้ใช้: ห้ามกระทบข้อมูลจริง** เพราะมีการอัปเดต timeline จริงไว้แล้ว

## ไม่มีการเขียนข้อมูล

แถบนี้**คำนวณสดตอน render จากวันที่ของงานที่มีอยู่** ไม่เพิ่มฟิลด์ ไม่เรียก `piSaveTask` ไม่แก้ค่าใน `PIMPL` ไม่แตะ Firestore

ถ้าลบโค้ดส่วนนี้ออก ข้อมูลจะเหมือนเดิมทุกประการ

## เงื่อนไขที่ตรวจแล้วว่ารองรับ

**ระบบพิกัดตรงกันอยู่แล้ว** — `.g-deprow` เป็น `position:relative` และอยู่ใน `.g-body{min-width:max-content}` ซึ่งกว้างเท่าแถวงาน (250px + ความกว้างไทม์ไลน์) วางแถบแบบ absolute ที่ `left: 250 + วันเริ่ม × dw` จึงตรงกับแถบงานด้านล่างพอดี

เป็นเทคนิคเดียวกับเส้นวันนี้ที่ใช้ `left:${250+tx}px` อยู่แล้ว

**ข้อมูลช่วงวันคำนวณได้จากของที่มี** — `byp[ph]` คือรายการงานของเฟสหลังกรอง และ `piSpan(d)` คืนช่วงจริงของงาน (งานแม่คิดจากงานย่อย) ไม่ต้องเพิ่มฟิลด์ใหม่

`renderPhaseTimeline()` คำนวณ min/max ต่อเฟสแบบเดียวกันอยู่แล้ว ยืนยันว่าข้อมูลรองรับ

## การคำนวณช่วงเฟส

ไล่ทุกงานใน `byp[ph]` เอา `piSpan(d)` แล้วหาวันเริ่มที่เร็วที่สุดกับวันจบที่ช้าที่สุด

ใช้ `piSpan` แทนค่า `d.s`/`d.e` ตรงๆ เพราะงานแม่อาจมีวันที่ค้างไม่ตรงกับงานย่อย — `piSpan` คิดจากงานย่อยจริงเสมอ

**คิดจากรายการที่ผ่านตัวกรองแล้ว** แถบจึงไม่ขัดกับสิ่งที่เห็นบนจอเมื่อเปิดตัวกรอง

ถ้าเฟสไม่มีงาน หรือไม่มีงานไหนมีวันที่ใช้ได้ → ไม่วาดแถบ

## รูปแบบ

แถวหัวเฟสสูง 24px ส่วนแถวงานสูง 38px ถ้าทำแถบเต็มความสูงจะดูหนักกว่าแถบงานจริงทั้งที่เป็นแค่สรุป

จึงใช้**แถบบาง 6px มุมมน** จัดกึ่งกลางแนวตั้ง ใช้สีของเฟสเอง (`--pc` ที่ตั้งไว้บน `.g-deprow` อยู่แล้ว) แบบโปร่ง เพื่อให้อ่านเป็นชั้นสรุป ไม่ใช่งานอีกชิ้น

```
● 02_Solution Definition (BRD)  28   ━━━━━━━━━━━━━━━━━━━━
    ● BRD Company Structure          ▭▭▭▭▭▭▭▭
    ● BRD General Accounting              ▭▭▭▭▭▭▭▭
```

## จุดที่ต้องระวัง และทางแก้

**ป้ายชื่อเฟสเป็น `position:sticky;left:4px` z-index 4** — พอเลื่อนจอไปขวา ป้ายจะลอยทับต้นแถบ ปล่อยให้แถบลอดใต้ป้าย (แถบใช้ `z-index:1`) ซึ่งเป็นพฤติกรรมปกติของ Gantt ทั่วไป

**แถวหัวเฟสมี `onclick="piTogglePhase()"`** — แถบตั้ง `pointer-events:none` การกดตรงแถบจึงยังยุบ/กางเฟสได้เหมือนเดิม ไม่เปลี่ยนพฤติกรรมที่ผู้ใช้คุ้นอยู่

## ผลพลอยได้

ตอนยุบเฟส ปัจจุบันเหลือแค่ป้ายชื่อ ไม่เห็นไทม์ไลน์เลย พอมีแถบนี้ การยุบทุกเฟสจะกลายเป็นมุมมองสรุปที่เห็นภาพรวมทั้งโครงการในจอเดียว

## ไม่ทำ

- ไม่แสดงความคืบหน้าในแถบ — ขอบเขตที่ขอคือช่วงเวลา ถ้าต้องการค่อยเพิ่มทีหลัง
- ไม่แตะแถบงาน การลาก การซูม หรือ `renderGantt()` ของหน้า ROI
- ไม่เพิ่มฟิลด์ ไม่แตะชั้นบันทึกข้อมูล

## การตรวจสอบ

1. แถวหัวเฟสมีแถบ และตำแหน่งซ้าย/ความกว้างตรงกับขอบเขตของงานในเฟสนั้น
2. เฟสที่ไม่มีงาน หรืองานไม่มีวันที่ → ไม่มีแถบ ไม่มี error
3. เปิดตัวกรอง แถบหดตามรายการที่เหลือจริง
4. กดที่แถบยังยุบ/กางเฟสได้
5. ยุบทุกเฟสแล้วยังเห็นแถบครบทุกเฟส
6. **ไม่มีการเรียก `piSaveTask` / `DB.saveItem` จากโค้ดที่เพิ่ม** — ตรวจด้วยการอ่าน diff
7. `node --check` ผ่าน · ไม่มี JS error

## รอบที่ 2 — ใส่ชื่อเฟสลงในแถบ

**วันที่:** 2026-08-06 (ต่อจากรอบแรก)

ผู้ใช้เห็นผลจริงแล้วขอให้แถบแสดงชื่อ เหมือนแถบงานอย่าง `BRD Company Structure & General Setup`

### เงื่อนไขที่บังคับให้แถวต้องสูงขึ้น

แถบงาน `.g-bar` **สูง 28px** แต่แถวหัวเฟสสูงแค่ **24px** — เตี้ยกว่าตัวแถบที่จะใส่เข้าไป จึงต้องเพิ่มความสูงแถว ไม่มีทางเลี่ยง

ผู้ใช้เลือกแบบ**กระทัดกว่าแถบงาน**: แถว 30px · แถบ 22px · ชื่อ 11px — เล็กกว่าแถบงาน (28px/12px) อย่างชัดเจน ลำดับชั้นระหว่างเฟสกับงานจึงยังอ่านออกจากขนาด

### เรื่องชื่อซ้ำ — ตรวจแล้วว่าเป็นแพทเทิร์นเดิมของแอป

กังวลตอนแรกว่าชื่อเฟสในแถบจะซ้ำกับป้ายด้านซ้าย แต่**แถวงานทำแบบนี้อยู่แล้ว** — ชื่ออยู่ทั้งใน `.g-lab` และใน `.g-bname` การทำแบบเดียวกันกับเฟสจึงสอดคล้อง ไม่ใช่ของใหม่

### จำกัดขอบเขตความสูง

`.g-deprow` **ถูกใช้โดยหน้า ROI ด้วย** (`renderGantt`) การแก้กฎกลางจะทำให้แถวกลุ่มของหน้านั้นสูงตามทั้งที่ไม่มีแถบเฟส

จึงใส่ `height:30px` ไว้ในกฎที่จำกัดขอบเขตอยู่แล้ว (`#piGantt .g-deprow,#apGantt .g-deprow`) **กฎกลาง `.g-deprow{height:24px}` ไม่ถูกแตะ**

### แยกจากแถบงานด้วยสีของเฟส

ถ้าหน้าตาเหมือนแถบงานเป๊ะจะแยกไม่ออกว่าอันไหนเฟสอันไหนงาน จึงย้อมด้วย `--pc` (สีเฟสที่ตั้งบนแถวอยู่แล้ว) — พื้น 12% ขอบ 38% จุดและตัวอักษรเป็นสีเต็ม เข้าชุดกับป้ายชื่อเฟสด้านซ้ายที่ใช้สีเดียวกัน

### ชื่อยาวกว่าแถบ

`overflow:visible;white-space:nowrap` ชื่อล้นออกนอกแถบได้ เหมือนแถบงานสั้น ๆ ที่มีอยู่แล้ว และ `min-width` เป็น 6px เท่าแถบงาน

จำลองกับข้อมูล seed: `01_Planning & Kick-off` (แถบ 75px) และ `07_On-Going Support` (แถบ 20px) ชื่อจะล้นออกมา ส่วนอีก 5 เฟสชื่ออยู่ในแถบพอดี

### ไม่มีอะไรพังจากการเพิ่มความสูง

`drawPIDeps()` วาดเส้นเชื่อมงานจาก `getBoundingClientRect()` ทุกจุด จึงปรับตามความสูงใหม่เอง ไม่มีที่ไหนใน Gantt hardcode ความสูงแถว

### ยังไม่เขียนข้อมูลเหมือนเดิม

ตรวจ diff แล้ว 0 คำสั่งเขียน — ยังเป็นการอ่านและวาดล้วน

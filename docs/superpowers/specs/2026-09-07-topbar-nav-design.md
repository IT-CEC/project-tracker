# ย้ายการนำทางจาก sidebar ซ้ายขึ้นมาไว้บนแถบหัว

**วันที่:** 2026-09-07
**ขอบเขต:** `index.html` — ชั้นนำทางและเลย์เอาต์เท่านั้น ไม่แตะชั้นข้อมูล

## ที่มา

ต้องการดีไซน์ตามเว็บบริษัท civilengineering.co.th — พื้นขาว ตัวอักษรน้ำเงิน จุดเน้นสีแดง
เมนูกึ่งกลาง และ `+` บอกว่าเมนูไหนมีเมนูย่อย

ระหว่างทำ mockup พบว่า **sidebar กับแท็บบน topbar ทำงานซ้ำกันอยู่แล้ว** — `data-pv`/`data-bv`
ของ `.sb-item` ชี้ไปที่ `setProjView()` / `setBrView()` ตัวเดียวกับที่ `#projToggle` เรียก
และในโค้ดก็มีบรรทัด `.topbar .projtabs{display:none!important}` พร้อมคอมเมนต์
*"toggles moved into the sidebar as sub-views"* — คือเคยแก้ความซ้ำนี้ด้วยการซ่อนแท็บบนไปแล้ว

จึงเลือกทางกลับกัน: ให้แถบหัวเป็นตัวนำทางเดียว แล้วตัด sidebar ทิ้ง

## โครงใหม่

```
[โลโก้] │ ระบบติดตามงาน ERP     [เมนูกึ่งกลาง]     [⛶ นำเสนอ] [CE ผู้ใช้] [☰]
────────────────────────────────────────────────────────────────────────────
ชื่อหน้า
[ตัวกรอง…]                                              [+ เพิ่ม …]
```

เมนูกึ่งกลาง 4 รายการ ครอบคลุมปลายทางเดิมครบทั้ง 8

| เมนู | เมนูย่อย |
|---|---|
| แผนงานโครงการ **+** | ภาพรวมแผนงานโครงการ · รายการความต้องการ · รายการรายงาน 3 ระดับ · ติดตามสถานะ |
| กระบวนการ Oracle | — |
| Automation **+** | ภาพรวมแผนงานโครงการ · วิเคราะห์ผลความคุ้มค่า |
| ตั้งค่า | — |

`+` มีเฉพาะเมนูที่กางเมนูย่อยจริง ถ้าใส่ให้ครบทุกอันมันจะกลายเป็นของประดับ
แล้วผู้ใช้จะกดเมนูที่ไม่มีอะไรกางแล้วงง

## กุญแจสำคัญ: เมนูย่อยคือ `.sb-item` ชุดเดิมทั้งดุ้น

รายการทั้ง 8 ในดรอปดาวน์ **คือ element เดิมจาก sidebar ที่ย้ายมาทั้งก้อน** — คลาส `.sb-item`
กับ `data-tab`/`data-pv`/`data-bv` เหมือนเดิมทุกตัวอักษร ผลคือ

- `updateNavActive()` ที่วน `.sb-item` — **ไม่ต้องแก้**
- ตัวจับคลิกที่ผูกกับ `.sb-item` — **ไม่ต้องแก้**

เหลือแค่เพิ่มการไฮไลต์ `.tb-a` บนแถบหัว และการปิดดรอปดาวน์ ความเสี่ยงจึงต่ำกว่าการเขียนตัวนำทางใหม่มาก

## ปุ่มที่เคยอยู่บนแถบหัว ย้ายไปตามชนิดของมัน

| ปุ่ม | เป็นอะไร | ไปอยู่ที่ |
|---|---|---|
| `⛶ นำเสนอ` (`#fsBtn`) | โหมดของทั้งระบบ ไม่เปลี่ยนตามหน้า | คงไว้บนแถบหัว |
| `+ เพิ่ม …` (4 ปุ่ม) | การกระทำของหน้านั้น เปลี่ยนตามหน้า | ท้ายแถบตัวกรอง `.bar` ของหน้าตัวเอง |
| `#crumbNow` | ชื่อหน้า | บนสุดของเนื้อหา (`.pagehead`) |

`syncTopAdd()` สลับการแสดงผลด้วย `id` ไม่ได้ผูกกับตำแหน่งใน DOM ปุ่มจึงย้ายบ้านได้โดยไม่ต้องแก้ฟังก์ชัน

ส่วนท้าย sidebar (ชื่อผู้ใช้ · `#syncBadge` สถานะเชื่อมต่อ · ออกจากระบบ) ย้ายเข้าเมนูผู้ใช้บนแถบหัว
`#syncBadge` คง id และ `.sb-txt` ไว้ เพราะ `DB.onStatus` เขียนลงไปโดยตรง

## สี

ยึดจากเว็บบริษัท — พื้น `#fff` · ตัวอักษร `#002453` · เน้น `#eb0029`

| สภาพ | หน้าตา |
|---|---|
| ปกติ | ตัวอักษรน้ำเงิน · `+` แดง |
| ชี้เมาส์ | ตัวอักษรแดง |
| กางเมนูย่อย | ตัวอักษรแดง · `+` เปลี่ยนเป็นจุดแดง |
| หน้าปัจจุบัน | ตัวอักษรแดงหนา · ขีดแดงใต้เมนู |

ธีมมืดสลับเป็น `#1c1c1e` / `#e8eef6` / `#ff5470` และ **โลโก้ต้องกลับค่าความสว่าง**
(`invert(1) hue-rotate(180deg)`) เพราะไฟล์โลโก้เป็นตัวอักษรสีเข้มที่ทำมาสำหรับพื้นขาว
วิธีนี้กลับสว่าง-มืดโดยคงเฉดสีเดิม เครื่องหมายจึงยังเป็นสีแดง

## จอแคบ

| ความกว้าง | เปลี่ยนอะไร |
|---|---|
| ≤ 1240px | ซ่อนชื่อระบบกับเส้นคั่น |
| ≤ 1080px | ซ่อนเมนูกึ่งกลางกับชื่อผู้ใช้ — ใช้ `☰` แทน |

`☰` เปิดเมนูรวมที่มีครบทั้ง 8 รายการ จัดกลุ่มแบบเดียวกับ sidebar เดิม
จึงทำหน้าที่แทน drawer เดิม (`.app.side-open .sidebar`) ที่ถูกตัดไปพร้อมกัน

## ไม่ทำ

- **ไม่เพิ่มไอคอนที่ระบบไม่มีอยู่จริง** — mockup มีช่องค้นหา สลับ EN/TH และกระดิ่งแจ้งเตือน
  ตามเว็บบริษัท แต่ระบบนี้ไม่มีฟังก์ชันพวกนั้น (สลับธีม/ภาษาอยู่ในหน้าตั้งค่า)
  ใส่ไปก็เป็นของตายที่กดแล้วไม่เกิดอะไร
- ไม่แตะชั้น persistence · โมเดลข้อมูล · ฟังก์ชัน render ใดๆ
- ไม่เพิ่มหน้า "ภาพรวม" เข้าเมนู — เดิม sidebar ก็ไม่มี เข้าได้จากการ์ด cockpit เท่านั้น
- ไม่ลบ CSS/โค้ดที่ตายแล้วของ `#projToggle` `.brand` `.dock` — ทุกจุดมี null guard อยู่แล้ว
  การรื้อไปแตะฟังก์ชันสลับมุมมองที่ทำงานดีอยู่ ได้ไม่คุ้มเสีย

## การตรวจสอบ

1. ปลายทางครบ 8 — เปลี่ยน panel ถูก · view ที่ควรแสดงแสดงจริง · ชื่อหน้าตรง · เมนูบนแถบไฮไลต์ถูก
2. **คลิกจริง** ผ่านดรอปดาวน์ · เมนูตรง · เมนูรวม · โลโก้ — ไปถูกหน้าทุกทาง และดรอปดาวน์ปิดเองหลังเลือก
3. ปุ่ม `+ เพิ่ม …` อยู่ในแถบตัวกรองของ view ตัวเอง และเห็นทีละปุ่มตามหน้า
4. ไม่มีการเลื่อนแนวนอนที่ 1600 · 1440 · 1280 · 1080 · 900 · 375
5. ธีมมืด: พื้นแถบหัว `rgb(28,28,30)` · ตัวอักษร `rgb(232,238,246)` · โลโก้อ่านออก
6. ไม่มี JS error · ไม่มีไฟล์โหลดไม่สำเร็จ (รวมถึงโลโก้ ซึ่ง **ต้อง `git add`** ไม่งั้น 404 บนเว็บจริง)
7. ของเดิมไม่พัง — regression ชุด PR #46–#62 ผ่านครบ · ไม่มี panel ไหนพัง
8. **`DB.saveItem` / `DB.deleteItem` ไม่ถูกเรียกเลยตลอดการทดสอบ** และ diff ไม่มีบรรทัดไหนแตะชั้นข้อมูล
